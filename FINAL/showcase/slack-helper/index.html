Claude-in-Slack helper

A Slack bot that answers staff questions from a small internal knowledge base, cites the document it used, and says "I don't know" when the docs do not cover it.

01What it does

Someone @mentions the bot in a channel or sends it a DM, and it replies in the thread with the answer and a Sources: line naming the policy document it read. Its brain is Claude Code run headlessly with an MCP server over seven markdown docs, the same setup staff already use at their desks, so the skills and prompts they share are the objects the bot runs on. When the docs do not cover the question it says "I don't know" and names the channel to ask, and when the question is ambiguous it asks which policy is meant instead of picking one.

02Why this design

  • Claude Code headless is the brain. The bot is claude -p plus an MCP server. The skills, prompts and MCP servers that staff share in their own Claude Code sessions are the same objects the bot uses, so improving one improves both. There is no second bot framework to keep in sync, and one place to maintain.
  • The MCP server is the only door to the knowledge base. Claude Code is launched with no built-in tools (--tools ""), only the three read-only MCP tools allowed, and --permission-prompts none. The worst a prompt injection in a Slack message can do is read the same policy docs anyone in the company can read. The knowledge base itself is plain markdown: correcting a policy is editing a file, with no embeddings, no index to rebuild and nothing to redeploy.
  • Refuse when the docs have no answer. If the knowledge base does not cover the question, the reply is "I don't know, ask #it-help" rather than a guess, and an ambiguous question gets a clarifying question back. The eval checks all three rules on every run: fact found and source cited, refusal, clarification.
  • Feedback reactions are the keep-or-retire signal. A thumbs up or thumbs down on a bot reply appends a line to feedback.jsonl with the question, the sources and the cost. A weekly jq over that file gives an accuracy signal without a dashboard, and it is the number that decides whether the tool stays.

03Architecture

A terminal front-end, cli.py, calls the same answer() function as the Slack handler, which is how the demo and the eval were recorded without a workspace. BRAIN=api swaps Claude Code for the Anthropic SDK with the same tool functions; see Limitations.

06Run it yourself

Needs Python 3.11+, and either Claude Code on PATH (logged in) or an ANTHROPIC_API_KEY. Code: github.com/Mild-Solvent/CV/tree/main/projects/claude-slack-helper

cd projects/claude-slack-helper
make setup                                   # venv + pip install -r requirements.txt
make test                                    # 19 unit tests, no model calls, about 1 s
.venv/bin/python cli.py "How many days of PTO do I get?"
.venv/bin/python cli.py --repl               # multi-turn; earlier turns are passed as thread context
make evals                                   # 12 real questions, scorecard, writes evals/last_run.md

Connecting a Slack workspace is seven steps in the README (create the app, Socket Mode, bot scopes, event subscriptions, two tokens, make slack). The eval is 12 calls and about a dollar, so changing the system prompt and re-running it is cheap.

07What I would watch in production

The metric is answered-and-useful per week: questions the bot answered (not refused) that got a thumbs up or no thumbs down, from feedback.jsonl. Three numbers, three trip-wires:

  • Thumbs-down rate. Above 20% of ratings for two weeks running means wrong answers, which is worse than no bot. Stop and read every downvoted thread before touching the prompt.
  • Unanswered rate. If answered-and-useful falls under about 15 a week for a month, the knowledge base is too small to matter or people have stopped asking. The honest move is to delete the bot and put the seven docs in a pinned Slack message.
  • Cost per answer. $0.025 on average at list price, printed by make evals after every change. The cheapest lever if usage climbs is HELPER_MODEL=claude-sonnet-5-5, about half the cost per answer in testing, then a lower --max-turns.

When it breaks

From the run-book. First 60 seconds, whatever the symptom: make test (code or deps broke), then one cli.py question (brain broke). If the CLI answers and only Slack is quiet, the problem is in Slack.

FailureHow you noticeFix
MCP server not startingEvery answer is "I don't know", or Claude says it has no tools, or the JSON has is_error.Run mcp_server/server.py by hand; the traceback names it. Usually the wrong mcp version or system Python instead of .venv: make setup, re-run make test.
Slack token expired or revokedProcess exits with invalid_auth, Socket Mode reconnects in a loop, or mentions get no eyes reaction.Reinstall the app in api.slack.com, copy the new bot token and app-level token into .env, restart. No code change. Untested here: built without a workspace.
Rate limit or API outageAnswers take 60 to 180 s then fail; rate_limit, overloaded or 529 in stderr; users see "Sorry, I hit an error".Check claude -p "say hi" raw; if that fails it is upstream. Wait or switch to BRAIN=api. The handler fails safe in the thread, so no restart is needed.
Knowledge base out of dateThumbs down in feedback.jsonl, or "the bot said 28 days but it's 30 now". The most likely failure, and the one nobody pages you about.Edit the markdown in kb/, update the matching line in evals/questions.yaml, make evals, commit the new last_run.md. Nothing to restart.

08Limitations

  • The Slack path has never talked to Slack. It is written against slack-bolt 1.30 and covered by five handler tests with a fake client, but there was no workspace in the build environment. The first live run will find something: a scope I missed, a payload field that differs. Budget an hour for it.
  • BRAIN=api is untested here. There was no ANTHROPIC_API_KEY in the build environment. The code follows the documented Messages API tool-use loop and its pure parts (cost table, source parsing) are tested, but it has not made a real request. Its cost figure is an estimate from the public price list and is labelled "estimate" in the output.
  • The eval is 12 questions with string checks. It shows the rules held on the cases I wrote, not that the bot is right in general. Read the answers, not just the table.
  • Search is keyword scoring over seven files. Right for this size and transparent when wrong. Past a few dozen docs it will miss synonyms; that is the point to add an embedding index behind the same search_docs tool, not before.
  • Not a security boundary. The bot has only the three read-only MCP tools, but anyone who can @mention it can read every doc in kb/. Nothing goes in kb/ that you would not post in #general.
  • Single process, in-memory map from bot reply to question for feedback. Restart the bot and reactions on earlier replies are not logged. Fine for one workspace; swap for SQLite if that hurts.
  • Costs are list price. The figure Claude Code reports is API list price; on a Team or Enterprise seat it comes out of that seat's quota instead. The dollar figure is still the right one for deciding whether the tool is worth it.
  • Size: 604 lines of app code (the target was 600) plus about 200 of tests. A new owner can read all of it in an hour.
